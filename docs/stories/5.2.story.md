# Story 5.2 — Drive & OFX Import Idempotency

**Status:** InProgress
**Epic:** 5 — Bug Fixes
**Agent:** @dev (Dex)

## Problem

Dois endpoints de classificação não verificam se o item já foi processado antes de criar
a transação/lançamento. Uma segunda chamada (erro de rede + retry, duplo clique, ou
qualquer re-envio) cria um lançamento duplicado para o mesmo comprovante.

- `api/drive-import/classify.ts`: não checa `pending.status` → cria 2ª transação
- `ofxApi.classifyOfxEntry`: não checa `p.status` → cria 2º `financial_entry`

Falta também proteção a nível de banco para o caso drive (constraint `(company_id, drive_file_id)`).

## Acceptance Criteria

- [ ] Chamar classify duas vezes para o mesmo Drive pending retorna o mesmo `transaction_id` sem criar duplicata
- [ ] Chamar classifyOfxEntry duas vezes para o mesmo OFX pending retorna o mesmo `financial_entry` sem criar duplicata
- [ ] Constraint de banco impede 2 transações com mesmo `(company_id, drive_file_id)`
- [ ] Itens já classificados (Drive ou OFX) não reaparecem na lista "Aguardando classificação"
