---

## Contexto

Para conformidade IFRS e credibilidade com investidores, o sistema deve validar continuamente que a equação fundamental da contabilidade é respeitada: **Ativos = Passivos + Patrimônio Líquido**.

---

## Valor de Negócio

Qualquer auditor ou investidor vai verificar se Ativos = Passivos + PL. Um sistema que não valida essa equação não é auditável. Esta story é o que transforma o sistema de "gestão de caixa" para "contabilidade corporativa" — pré-requisito para M&A.

## Escopo

**IN:**
- Função `validateAccountingEquation` no `ifrsEngine.ts`
- Componente `AccountingEquationAlert` no Dashboard
- Testes unitários (balanceado e desbalanceado)

**OUT:**
- NÃO corrigir automaticamente desbalanceamentos (apenas alertar)
- NÃO gerar relatório contábil completo (Epic 2)
- NÃO validar regime tributário (escopo futuro)

## Riscos

| Risco | Probabilidade | Impacto | Mitigação |
|-------|--------------|---------|-----------|
| Falso positivo por arredondamento | Média | Médio | Tolerância de R$0,01 com decimal.js |
| Performance: recalcular todo balanço a cada render | Média | Médio | Cache com TTL de 60s ou trigger manual |
| Confundir usuário com alerta sem contexto | Alta | Baixo | Mensagem explicativa com link para ajuda |

---

## Acceptance Criteria

- [ ] AC1: Função `validateAccountingEquation(companyId, period)` em `ifrsEngine.ts` que retorna `{ balanced: boolean, assets: Decimal, liabilities: Decimal, equity: Decimal, delta: Decimal }`
- [ ] AC2: Alerta visual no dashboard quando `balanced = false` (componente `AccountingEquationAlert`)
- [ ] AC3: Tolerância de R$0,01 para erros de arredondamento (usando decimal.js)
- [ ] AC4: Relatório de diagnóstico mostrando quais contas estão desbalanceadas
- [ ] AC5: Validação executada automaticamente ao gerar qualquer relatório de investidores (Epic 2)
